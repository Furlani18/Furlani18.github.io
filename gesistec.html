01

O desafioThe challenge

Um help desk só funciona se ninguém se perde: o cliente precisa abrir um chamado, conversar com a equipe e saber em que pé está; a equipe precisa priorizar, responder e mudar o status sem que nada fique para trás. E tudo isso para várias empresas, cada uma vendo só os próprios chamados.

A help desk only works if nothing gets lost: customers need to open a ticket, talk to the team and know where things stand; the team needs to prioritize, reply and update the status without dropping anything. And all of that for multiple companies, each one seeing only its own tickets.

Havia ainda uma restrição prática: o sistema precisava rodar numa hospedagem gratuita, o InfinityFree, que só executa PHP e MySQL.

There was also a practical constraint: it had to run on free hosting (InfinityFree), which only runs PHP and MySQL.

02

A soluçãoThe solution

  • Três perfis de acesso: admin (gerencia empresas, usuários e tipos de chamado), colaborador (atende) e cliente (abre e acompanha).
  • Chamados com conversa: cada ticket tem mensagens trocadas entre cliente e equipe, além de status e prioridade.
  • Histórico dentro da conversa: mudanças de status e prioridade aparecem no meio do chat (ex.: “Status alterado para Finalizado”).
  • Conta segura: “Esqueceu a senha?” com link por e-mail que expira, e bloqueio temporário após muitas tentativas.
  • Site institucional com formulário de contato, também protegido contra envio em massa.
  • Three access roles: admin (manages companies, users and ticket types), staff (handles tickets) and customer (opens and follows them).
  • Tickets as conversations: each ticket has a message thread between customer and team, plus status and priority.
  • History inside the thread: status and priority changes show up in the chat (e.g. “Status changed to Closed”).
  • Secure accounts: “Forgot password?” with an expiring email link, and temporary lockout after too many attempts.
  • Company website with a contact form, also protected against mass submissions.

Desafios e decisõesChallenges and decisions

01

De Node.js para PHPFrom Node.js to PHP

A primeira versão rodava em Node.js/Express, mas o InfinityFree não executa Node. Em vez de trocar de hospedagem, reescrevi o servidor como uma API em PHP, endpoint por endpoint, mantendo o front-end funcionando.

The first version ran on Node.js/Express, but InfinityFree can't run Node. Instead of switching hosts, I rewrote the server as a PHP API, endpoint by endpoint, keeping the front-end working.

02

Descrições que sumiamDisappearing descriptions

Os campos de descrição dos chamados não eram salvos corretamente. Segui o dado do formulário até o banco e corrigi o problema nas duas pontas, no front e no back-end.

Ticket description fields weren't being saved correctly. I traced the data from the form to the database and fixed the issue on both ends, front-end and back-end.

03

Sessão seguraSecure sessions

O login gera um token que vai no header X-Session-Token. O banco guarda só o hash SHA-256 dele, com data de expiração, e os endpoints protegidos conferem o perfil do usuário antes de agir.

Login issues a token sent in the X-Session-Token header. The database stores only its SHA-256 hash, with an expiry date, and protected endpoints check the user's role before acting.

04

Contra força brutaAgainst brute force

Uma tabela registra tentativas de login, recuperação de senha e contato por e-mail e por IP. Passou do limite na janela de tempo, bloqueia até esfriar.

A table records login, password-reset and contact attempts by email and IP. Exceed the limit within the time window and you're blocked until it cools down.

05

Deploy em um pushDeploy on push

Um workflow do GitHub Actions envia o site por FTP a cada push na main, ignorando arquivos .sql e de credenciais. Nada de subir arquivo na mão.

A GitHub Actions workflow uploads the site over FTP on every push to main, skipping .sql and credential files. No more manual uploads.

05

O que aprendiWhat I learned

  • Restrição de infraestrutura muda arquitetura, e reescrever com cuidado pode sair mais barato que trocar de ferramenta.
  • Segurança não é um recurso extra: hash de token, expiração, limite de tentativas e segredos fora do Git custam pouco no começo.
  • Automatizar o deploy elimina toda uma categoria de erro (“esqueci de subir aquele arquivo”).
  • Bug de persistência se resolve seguindo o dado de ponta a ponta, não chutando onde está o problema.
  • Infrastructure constraints shape architecture, and a careful rewrite can be cheaper than switching tools.
  • Security isn't an add-on: token hashing, expiry, rate limiting and secrets out of Git cost little up front.
  • Automating deployment removes a whole class of mistakes (“I forgot to upload that file”).
  • Persistence bugs are solved by following the data end to end, not by guessing where the problem is.
